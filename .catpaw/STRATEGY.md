# AI 开发工具协作策略

> **目的**：明确各工具分工，避免重复劳动，最大化额度利用。  
> **维护原则**：每次新增/切换工具时更新本文档。

---

## 工具画像对比

| 工具 | 类型 | 额度 | 擅长场景 | 短板 | 本项目用途 |
|------|------|------|----------|------|------------|
| **CatPaw** | **AI IDE** | 500 次/用户，单次 tokens 极大 | 完整 IDE 体验、代码编写/调试/运行一体化、大上下文 | 可能无 Agent 编排能力 | **主力开发**：日常编码、调试、运行、单文件深度优化 |
| **Qoderwork** | 本地 Agent | 每日签到 100 积分 + 付费额度 | 长上下文、多文件联动、复杂架构搭建、Agent 编排 | 额度有限、非完整 IDE | **辅助攻坚**：架构设计、脚手架生成、复杂逻辑、文档生成 |
| **Hermes (我)** | 桌面 Agent | 按需调用 | 规格文档、Prompt 工程、面试准备、项目规划 | 不直接写业务代码 | **大脑**：写 SPEC、设计 Prompt、规划里程碑、分析岗位匹配 |

---

## 核心定位

> **CatPaw 是完整 AI IDE** → 主力开发环境（写代码、调试、运行）  
> **Qoderwork 是本地 Agent** → 辅助攻坚（架构、脚手架、复杂推理）  
> **Hermes 是规划大脑** → 规格、Prompt、面试、调度

## 各工具 Prompt 模板

### CatPaw IDE —— 日常开发（中等 Prompt，聚焦实现）

```markdown
# 场景
你正在使用 CatPaw IDE 进行开发。

# 当前任务
<TASK_DESCRIPTION>

# 上下文
- 文件路径：<FILE_PATH>
- 相关规格：SPEC.md §<SECTION>
- 已有代码：<RELEVANT_SNIPPET>

# 要求
- 直接产出可运行代码
- 遵循 PEP 8 + Black 120 列
- 添加类型注解和 docstring
- 如需新建文件，说明路径

# 验收标准
<ACCEPTANCE_CRITERIA>
```

---

### Qoderwork —— 复杂架构（长 Prompt，多文件联动）

```markdown
# 角色
你是 <DOMAIN> 领域高级工程师，熟悉 <TECH_STACK>。

# 任务
在 `<REPO_ROOT>` 基于现有脚手架，实现 **<FEATURE_NAME>**（对应 SPEC §<SECTION>、US-<ID>）。

# 输入上下文
- SPEC 相关章节：<LINKS>
- 已有代码：<RELEVANT_FILES>
- 接口契约：<OPENAPI/PROTO_PATH>

# 交付物
- 核心实现：<FILES>
- 单测：`tests/unit/test_<feature>.py`
- 集成测：`tests/integration/test_<feature>_flow.py`

# 验收标准（AC）
<Given/When/Then>

# 约束
1. 复用现有基础设施（ToolRegistry/Config/Database）。
2. 对外接口符合 `openapi.yaml`。
3. 新增依赖需在 `pyproject.toml` 声明并 `uv lock`。
4. 代码通过 `pre-commit run --all-files`。

# 验收命令
```bash
make test-unit TEST=tests/unit/test_<feature>.py
make test-integration TEST=tests/integration/test_<feature>_flow.py
```
```

## 额度使用策略

| 工具 | 每日建议用量 | 使用时机 | 节省技巧 |
|------|-------------|----------|----------|
| **CatPaw** | 500 次/月（约 16 次/天） | 白天主力开发 | 1. 单次 Prompt 写清楚需求，避免反复追问<br>2. 复杂任务拆成多个独立 Prompt<br>3. 用我（Hermes）先写好 Prompt，直接复制到 CatPaw |
| **Qoderwork** | 签到 100 积分 + 按需付费 | 每晚 22:00 后集中攻坚 | 1. 只做架构/脚手架/复杂逻辑<br>2. 日常编码交给 CatPaw<br>3. 用我先写好 Prompt，直接复制 |
| **Hermes** | 按需 | 规划、文档、面试、Prompt 工程 | 1. 批量提问，一次问多个问题<br>2. 用 session_search 查历史，避免重复问 |

## 工具切换决策树

```
开始任务
  │
  ├─ 需要写规格/架构/面试准备？
  │   └─ 是 → 用 Hermes（我）
  │
  ├─ 需要跨文件、多文件联动、复杂架构搭建？
  │   └─ 是 → 用 Qoderwork（辅助攻坚）
  │
  ├─ 日常编码、调试、运行、单文件优化？
  │   └─ 是 → 用 CatPaw（主力 IDE）
  │
  └─ 不确定？
      └─ 先用 Hermes 分析任务复杂度，再分配工具
```

## 记录与追溯

- **Qoderwork Prompt** → 记录在 `.qoderwork/PROMPTS.md`
- **CatPaw 关键对话** → 截图或复制到 `.catpaw/notes/YYYY-MM-DD.md`
- **Hermes 对话** → 通过 session_search 自动追溯
