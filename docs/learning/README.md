# 学习手册 — TFT Agent Set 17

> 这套手册不是"项目说明书"，而是"学习路线图"。
> 项目根目录已经有 `ARCHITECTURE.md`、`DESIGN_DECISIONS.md`、`SPEC.md` 等工程文档，它们回答"**我们建了什么**"。
> 这套手册回答另一个问题：**"作为一个计算机专业的学生，我怎么真正学懂它、复现它、并优化它"**。

---

## 这套手册适合谁

适合已经具备 Python / 数据库 / Web 基础，第一次接触"LLM 应用 / RAG / Agent"这类系统的同学。
它的目标不是让你"会用"这几个名词，而是让你建立三个能力：

1. **看懂选型**——面对一个技术，能说出"为什么在这里用它，而不是别的"。
2. **复现系统**——能在一台干净的机器上把项目跑起来，并说清每一层在干什么。
3. **优化系统**——遇到性能/质量问题，能用"问题 → 定位 → 优化 → 验证"的闭环去解决，而不是凭感觉改。

## 项目当前的真实完成度（先泼一盆冷水，也先给一颗定心丸）

在开始学习前，你需要对项目"完成到哪一步"有清醒认知，否则会被文档里那些"生产级"描述误导。

**已经真正跑通、可以演示的主干链路：**

```
数据采集(Riot API + Data Dragon)
   → 阵容挖掘(Jaccard 聚类, 56 套阵容)
   → Agent 后端(LangGraph: Planner→Executor→Critic→Reflect, 11 个工具)
   → 前端(React 对话 UI + 阵容卡片 + 历史记录)
   → 认证与会话(JWT + SQLite)
```

这条"提问 → 流式推理 → 出阵容卡片"的链路是端到端通的。**作为毕设或学习项目，完成度相当高。**

**但有几个诚实的缺口，学习时要把它们当作"练习题"而不是"已完成"：**

第一，**RAG 和知识图谱是"代码写好了、但没经过真实验证"的状态**。`RAGEngine` 依赖 Milvus 向量库和 Neo4j 图数据库，这两个外部服务是否启动、是否灌入数据，目前不确定。`02-优化实战案例集` 里的第一个案例（BGE-M3 重复加载），正是这条线没经过压力检验才暴露出来的。

第二，**文档和实现存在漂移**。`ARCHITECTURE.md` 写的是 vLLM 部署 Qwen2.5-14B，但实际跑的是 LongCat-2.0 的远程 API；K8s、Prometheus、Grafana、LangSmith 这些更多是"规划"而非"已落地"。
> 这本身就是一个重要教训：**文档会随迭代失真，代码才是唯一的真相。** 读任何文档（包括本手册）时，养成"回到源码核对"的习惯。

第三，**测试、部署、短信验证是骨架**。`tests/` 目录存在但覆盖度有限，短信验证码大概率是 mock，生产部署只停留在文档。

一句话总结：**主干能跑、能演示、能讲清原理；但 RAG/图谱未经验证、有已知性能问题、工程化（测试/部署/监控）是占位。**
对一个学习者来说，这反而是好事——**一个"半成品"比一个"完美项目"更适合学优化**，因为它把问题留给了你。

## 学习这套系统需要的前置知识

不需要全部精通，但下面这些概念你需要"听说过、能查"：

- **Python 异步编程**：`async/await`、`asyncio`。后端 FastAPI 是全异步的。
- **SQL 基础**：`SELECT/JOIN/GROUP BY`。数据查询工具几乎全是 SQL。
- **HTTP 与 REST**：知道什么是请求/响应/状态码。
- **前端基础**：React 组件、`useState`、`useEffect`。
- **机器学习直觉**（可选但有帮助）：知道"向量""相似度""模型加载"大概是什么。

完全没接触过 LLM/RAG/Agent 没关系——`01` 文档会从"为什么需要它"讲起。

## 一个贯穿全手册的思维框架

无论看哪份文档，请记住这个"选型三问"，它是这套手册真正想教你的东西：

1. **它解决了什么问题？**（没有它会怎样？）
2. **为什么是它，而不是替代品？**（trade-off 是什么？）
3. **它的代价是什么，怎么优化？**（没有银弹，每个选择都有成本。）

举例：为什么用 SQLite 而不是 PostgreSQL？
- 解决了什么：关系型存储用户/会话/阵容数据。
- 为什么是它：单文件、零运维、自包含，项目初期不需要并发写的高可用。
- 代价与优化：并发写弱、无网络访问；等用户量上来再迁移 Postgres（代码里已为此预留了接口抽象）。

带着这三个问题去读 `01`，你会比"背诵技术栈表格"收获大得多。
